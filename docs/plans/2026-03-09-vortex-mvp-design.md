# Vortex MVP 设计文档（已评审）

- 日期：2026-03-09
- 设计范围：MVP（同步闭环）
- 技术栈：前后端分离，前端 React，后端 Java 25
- 核心验收指标：连续运行 7 天无数据丢失、无重复成功写入

## 1. 范围与边界

### 1.1 本期纳入
- 1 Flow = 1 目标平台（平台可配置）
- 基础可视化画布（拖拽、连线、运行状态）
- 手动触发
- 单数据库按 ID 拉取全量数据
- 过滤/转换支持：表达式 + 脚本
- 结果提取器支持：JSONPath + 脚本
- 批量拆分：按平台上限拆分，支持串行/并发，批次重试 N 次
- 完整可观测：单条 + 批次追溯、节点指标、可下钻

### 1.2 本期不纳入
- CDC 触发
- 异步状态查询闭环
- 多数据源插件化实现（接口可预留，首版仅实现数据库）

## 2. 方案选择

### 2.1 候选方案
1. 单体后端 + 固定节点执行器（最快）
2. 模块化单体 + 节点插件化执行引擎（推荐）
3. 事件驱动编排（复杂度高，不适合 MVP）

### 2.2 结论
采用方案 2：模块化单体 + 节点插件化执行引擎。

理由：在保持 MVP 交付速度的同时，为后续 CDC、异步查询、新节点扩展保留清晰边界，且更利于稳定性治理。

## 3. 总体架构

### 3.1 前端（React）
- Flow 画布模块：节点拖拽、连线、启停、节点状态染色
- 节点配置模块：各节点配置表单
- 运行观测模块：节点 in/out/fail、批次进度、失败明细、单条追溯入口

### 3.2 后端（Java 25，模块化单体）
- flow-definition：Flow/节点/连线/版本管理
- execution-engine：DAG 调度、运行上下文与批次上下文管理
- node-plugins：手动触发、DB 拉取、过滤、转换、拆分、推送、结果提取器
- reliability-core：幂等、去重、批次重试、失败回放
- trace-observability：节点指标、批次日志、单条轨迹、审计日志

### 3.3 存储分层
- 配置库：Flow 定义、节点配置、平台配置
- 运行库：运行批次、节点执行、单条轨迹、错误明细
- 映射表：内部 ID ↔ 平台 ID（唯一键：business_id + platform_code）

## 4. 核心数据流与状态流

### 4.1 主链路（同步）
1. 手动触发输入业务 ID
2. 数据整合器去重并写待处理池
3. 按 ID 从数据库拉取全量数据
4. 过滤节点执行表达式/脚本
5. 转换节点执行映射/表达式/脚本
6. 按平台上限切批（串行/并发可配）
7. 推送每批并记录请求响应
8. 结果提取器提取状态、平台 ID、错误信息
9. 更新映射表与单条状态，落全链路日志与指标

### 4.2 运行状态机
- 批次级：PENDING -> RUNNING -> SUCCESS | PARTIAL_FAIL | FAIL
- 重试级：FAIL/PARTIAL_FAIL -> RETRYING(n) -> SUCCESS | FAIL_FINAL
- 单条级：NEW -> FILTERED | TRANSFORMED | PUSHED_SUCCESS | PUSHED_FAIL

## 5. run_id 策略

- run_id 在 Flow 中可定义生成策略，支持“接口型生成器”。
- 平台内置默认生成器：UUID（仅在未配置接口时启用）。
- 执行入口先获取 run_id，所有批次、节点日志、单条轨迹强制挂在该 run_id 下。
- 若接口生成 run_id 失败：本次运行直接终止，状态记为 FAIL_INIT；不降级到 UUID。

## 6. 错误处理与恢复

### 6.1 失败分层
- 配置期失败：参数非法/缺失，禁止启动
- 运行期失败：节点异常，进入重试或终止
- 外部依赖失败：超时/限流/5xx，按重试策略处理

### 6.2 重试与恢复
- 粒度：批次级
- 策略：固定间隔或指数退避，可配最大 N 次
- 恢复点：从失败批次继续
- 幂等：business_id + platform_code，防重复成功写入

### 6.3 数据一致性
- 先落执行记录，再推进状态
- 映射表只保留最新成功映射
- 历史 attempt 全量保留在轨迹日志

## 7. 可观测与追溯

- 节点级：状态、in/out/filter/fail/async、耗时、吞吐
- 批次级：总数、成功、失败、过滤、重试次数、总耗时
- 单条级：按业务 ID 回看全生命周期轨迹（run/batch/node）
- 运维能力：失败批次手动重推、按 run_id/batch_no 快速定位

## 8. 测试与验收

### 8.1 测试分层
- 单元：表达式、脚本沙箱、JSONPath、拆分算法、幂等
- 集成：成功/部分失败/全失败/重试耗尽
- E2E：画布配置、执行监控、单条追溯闭环
- 稳定性：7 天长稳 + 故障注入（DB 抖动、平台超时等）

### 8.2 验收硬门槛
- 连续 7 天：0 数据丢失、0 重复成功写入
- 失败批次可恢复率 100%
- 任意业务 ID 在 2 分钟内可定位完整轨迹

### 8.3 发布准入
- P0/P1 用例全部通过
- 7 天稳定性与故障注入回归通过
- 任一硬门槛不达标，不发布
